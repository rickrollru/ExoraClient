# Exora Client — техническое задание и контекст проекта

Exora Client — клиент для DDraceNetwork (DDNet) на базе TClient с новым интерфейсом, HUD, визуальными
эффектами и переработанным редактором карт. В исходном коде и настройках проект называется XClient
(каталоги `xclient`, префикс настроек `xc_`); это внутреннее имя, его не переименовываем, чтобы не терять
настройки пользователей.

Документ — основной источник требований и решений. Перед любой работой прочитать целиком.

| Документ | Содержание |

## 1. Работа с владельцем проекта

- Владелец проекта — **Крутой**. Обращаться только так, не по имени.
- Язык общения — русский, тон неформальный.
- Владелец не пишет код: весь код делает исполнитель. От владельца — запуск, проверка, скриншоты, отчёты об ошибках.
- Результаты объяснять простыми словами, без лишней теории.
- Целевая платформа владельца: Windows, Visual Studio 2022 + CMake + Rust.
- Перед крупной переделкой — коротко описать план и получить согласие.

## 2. Цели и ограничения

**Цель.** Современный клиент DDNet с полностью новым визуальным стилем по образцу популярных клиентов
Minecraft (Expensive, Space Visuals, Nursultan): меню, HUD, визуальные эффекты, удобство (QoL).

**База.** Форк TClient (https://github.com/sjrc6/TaterClient-ddnet), remote `upstream`. Лицензия zlib, как у DDNet:
изменённая версия обязана быть явно помечена как изменённая (README).

**Обязательные ограничения:**
1. **Никаких читов:** боты, автохук, автофейз, ESP, изменение ввода (Snap Tap, «лучший ввод» и т.п.) — запрещены.
   Только визуал, HUD и удобство.
2. **Совместимость с серверами DDNet:** сетевую часть и физику не меняем. Всё, что пишется в карты (редактор), —
   стандартные возможности формата карты DDNet.
3. **Код из других клиентов** переносим только с проверкой лицензии; по умолчанию берём идеи, код пишем свой.
   Исключение — Flower: разрешение автора на код и ресурсы в `docs/xclient/third_party/flower_permission.png`.
4. Клиент пока для личного использования, не для публичного релиза.

## 3. Дизайн-система

Структура — по референсам (Expensive redesign, Space Visuals), цвета свои. Интерактивный HTML-прототип всех
экранов — у владельца в claude.ai (артефакт «DDNet Client UI»), при необходимости запросить скриншоты.

- **Меню** полностью заменяет стандартное (Esc), а не открывается окном поверх.
- **Навигация:** верхний бар — лого слева, капсула вкладок с иконками по центру, справа поиск / язык / тема / аватар.
- **Компоновка:** контент слева, панель деталей справа.
- **Карточки настроек:** две колонки; шапка — название, серое описание, плашка бинда, переключатель; под разделителем
  все параметры сразу, без вложенных окон. 2–4 варианта — segmented control вместо выпадающего списка.
  Слайдер на всю ширину: название слева, значение справа.
- **Типографика:** без капса. Три уровня: жирный заголовок, серое описание, средне-серые названия параметров.
  Шрифты: Manrope (основной), Onest, Unbounded — выбор в настройках.
- **Темы:** тёмная и светлая. Акценты: голубой #4F8CFF, мятный #3DD6A4, оранжевый #FF8A3D, розовый #FF5C8A,
  лаймовый #B6E83C, красный #FF4D4D, белый (монохром). Акцент по умолчанию — голубой (`xc_ui_accent 0`).
- **Тёмная тема:** фон #0A0B0E, панели rgba(17,19,24,0.82), карточки rgba(28,31,38,0.9), обводка 1px
  rgba(255,255,255,0.07), текст #F2F3F5, вторичный #C9CCD2, приглушённый #8C919B.
- **Скругления:** окна и панели 14–18px, карточки 10–14px, мелкие плашки 6px.
- **Настраивается пользователем:** уровень анимаций, фон меню (блюр игры / анимация / карта / своя картинка),
  язык RU/EN, масштаб интерфейса (1080p–4K), пресеты производительности (Низкое / Среднее / Высокое + ручные
  переключатели эффектов), звуки интерфейса.
- **Логотип:** «крюк-X» — `docs/xclient/logo/files/`; в клиенте рисуется `XcUi::DrawLogo`, акцентная линия = цвет темы.

## 4. Архитектура

Движок DDNet не заменяется — клиент встраивается в него.

1. **Движок DDNet** рисует игру как обычно (рендер-поток, OpenGL / Vulkan).
2. **Рендер-модуль** (`src/engine/client/backend/xclient/xc_renderer.cpp`) — собственные команды `CMD_XC_*` в
   командном буфере, выполняются в рендер-потоке на OpenGL 3.3; GL-состояние сохраняется и восстанавливается.
   SDF-фигуры с instancing, bloom (dual Kawase), блюр под меню, захват силуэта ти для неонового контура.
   Без GL 3.3 (Vulkan, GL1, GLES) модуль выключен (`XcRender::IsAvailable()`), эффекты рисуются упрощённо через
   `IGraphics`. Шлюз в игре — `components/xclient/fx_renderer.cpp`.
3. **Интерфейс** (меню, HUD, редактор) — Dear ImGui 1.91.9b (`src/engine/external/imgui`, растеризация шрифтов через
   FreeType). Мост `ui/imgui_backend.cpp`: ввод из `IInput`, вывод треугольниками через `IGraphics` — работает на
   любом бэкенде. Пока меню открыто, игра ввод не получает.
4. **Спрайтовые эффекты** «Мягкий свет» (`components/xclient/sprite_fx.cpp`, текстуры `data/xclient/fx`) — через
   `IGraphics`, любой бэкенд. Все PNG эффектов должны быть RGBA (PNG32).
5. **Редактор карт** — `CXcEditorUi` (`components/xclient/editor/xeditor*.cpp`) рисует весь кадр редактора на ImGui;
   логика, история (Ctrl+Z) и формат карты — родные DDNet. Классические попапы свойств вызываются в режиме захвата
   (`SXcCapture`): отдают списки свойств и кнопок, панель рисует их своими виджетами.

**Где что в коде DDNet/TClient:** компоненты — `src/game/client/components/` (`CComponent`, регистрация в
`gameclient.h/.cpp`); компоненты TClient — `components/tclient/`; стандартное меню — `components/menus*.cpp`;
рендер-бэкенды — `src/engine/client/backend/`, `graphics_threaded.cpp`, `backend_sdl.cpp`; редактор — `src/game/editor/`.

## 5. Состояние проекта

Подробности по каждому пункту — в `docs/xclient/DEVLOG.md`.

**Меню** (`components/xclient/ui/`): Главная (профиль с превью ти и статистикой ddnet.org, друзья, новости,
музыка, ссылки, инструменты), Серверы, Визуалы, Конфиги (обмен коротким кодом), Демки, Голосование, Настройки
(Интерфейс, Игрок/дамми, Управление, Звук, Чат, Графика (разрешение, режим окна, соотношение сторон), HUD, Фон, Текстуры, TClient, DDNet — полные списки
настроек с поиском). Поиск по настройкам (Ctrl+F), режим стримера (скрытие ников), наборы звуков интерфейса (Exora / Flower),
пресеты темы и производительности, тосты, звуки интерфейса, свои фоны (картинки и GIF), карточка карты по Esc.

**HUD** (`components/xclient/hud/`): ватермарка, таймер, скорость, оружие, клавиши, музыка, мини-топ, баннер
финиша, тосты, эффекты (аналог зелий: фриз, джетпак, бесконечный хук... с таймерами); редактор расположения; своя таблица игроков; оформление чата, колёс эмоций, наблюдения, голосования,
плашек ников; режим фокуса.

**Визуалы** (`components/xclient/*.cpp`): 3D-косметика из Flower (крылья, рюкзаки, шапки, питомцы; 2D «наш стиль» и 3D),
попадания пуль, погода (15 видов и свои картинки/гифки), шлейфы, кольца прыжка и пыль, конус/нимб/корона, свои шапки
(редактор косметики), плащ, желейный ти, стили хука, неоновый контур, свечение предметов и снарядов, лазеры,
ледяная аура, удар молотком, свой взрыв, финиш/смерть/появление/телепорт/чекпоинт, стрелки на игроков за экраном,
размытие движения ти и прицела, линии скорости, отдача прицела, тряска камеры, вспышки экрана, звуки событий, цвет мира и виньетка, прицел, летающие огоньки, градиентные и
летающие ники, замена стандартных эффектов, тонкая настройка свечения; из Flower — атмосфера (время суток, лучи, туман),
шейдер на ти, блок под прицелом, физика и единая форма частиц, стили взмаха молотка и оружие в руке, эффекты смерти
(молния, душа, сердечки, пиксели) и метка последней смерти.

**Музыкальный плеер** (`components/xclient/music/`): системные медиа-сессии Windows (SMTC, C++/WinRT), на Linux —
MPRIS через `playerctl`.

**Редактор карт** (`components/xclient/editor/`): новый интерфейс (верхняя панель, дерево слоёв с перетаскиванием,
свойства, капсула инструментов, Ctrl+K), окна файлов и вопросов, доки (огибающие таймлайном и графиком с
кривыми Безье, настройки сервера, история), инструменты (ластик, заливка, умная заливка с автомаппером, замена,
волшебная палочка, пипетка, инспектор), префабы, коррекция картинок, фоны карты, GIF в картах, пресеты анимаций,
зоны тюнинга с объяснениями, совместное редактирование по сети (LAN / Radmin VPN), масштаб интерфейса.

**Требует проверки на Windows:** сборка и работа музыкального плеера; совместное редактирование через Radmin VPN
(включая запрос брандмауэра); чёткость шрифтов после перехода на FreeType; последние изменения редактора.

6. **Редактор:** подсветка зон тюнинга цветом на карте; общая шлифовка. «Блоки не по сетке» не делаем — решение владельца.

8. **Оптимизация:** сделано — быстрый мост ImGui (HUD в 3–8 раз дешевле), режим низкой задержки ввода. Дальше: отзывы

## 7. Правила разработки

- Работа ведётся в git; коммит после каждого законченного шага, затем push в рабочую ветку.
- После каждого шага — запись в `docs/xclient/DEVLOG.md` (дата, что сделано, файлы, настройки, как проверено);
  при изменении состояния или бэклога — обновить разделы 5–6 этого файла.
- Наш код — в `src/game/client/components/xclient/` (редактор — `xclient/editor/`, рендер-модуль —
  `src/engine/client/backend/xclient/`). Вставки в файлы DDNet/TClient помечаются комментарием `// XClient`
  и делаются минимальными.
- Настройки — префикс `xc_`, объявление в `src/engine/shared/config_variables_xclient.h`, сохраняются в
  `settings_xclient.cfg`.
- Строки интерфейса пишутся по-английски и переводятся через `XcUi::Tr()` (таблица `ui/lang.cpp`).
- Стиль кода — как в окружающем коде DDNet (табы, `m_` / `p` / `a` / `v` префиксы, комментарии по делу).

## 8. Сборка и проверка

**Windows (владелец):** Visual Studio 2022, пресеты `CMakePresets.json` «Exora Client Release/Debug» (Ninja, без
FFmpeg). Запускать `out\build\...\DDNet.exe`, не `out\install\...`. Рядом собирается `DDNet-Server.exe` для
локального сервера.

**Облако (без Windows):** сборка на Linux (`build/`, ninja), запуск DDNet-Server и клиента на Xvfb, управление через
`xdotool`, скриншоты `import`, короткие эффекты — видео `ffmpeg -f x11grab`, звук — `SDL_AUDIODRIVER=disk`
(48 кГц, стерео, s16). Окно ищется по заголовку «Exora». Для кириллицы в `xdotool type` — `LC_ALL=C.UTF-8`
(ввод может терять символы — по возможности открывать окна через меню, а не набором текста).

**Известные особенности:**
- В облаке FPS ~20, у владельца — высокий: логику, зависящую от кадров, проверять на независимость от FPS.
- Код Windows-плеера (C++/WinRT) в облаке собрать нельзя; CMake проверяет его тестовой программой
  (`XC_MEDIA_WINRT_WORKS`) и при неудаче собирает клиент без плеера.
